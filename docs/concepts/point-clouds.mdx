# Point Clouds

A **point cloud** is a collection of data points in a 3D coordinate system, each representing a sampled location on the surface of an object or environment. Every point carries at minimum an XYZ position; most modern captures also include intensity values, RGB colour from photography, and classification codes (ground, vegetation, building, water, and so on).

Point clouds are the primary output of reality capture: **terrestrial LiDAR** (tripod-mounted scanners for interior documentation, heritage recording, and site surveys), **airborne LiDAR** (aircraft or drone-mounted scanners for terrain modeling, forest inventory, and urban mapping), and **photogrammetry** (3D geometry derived from overlapping photographs, producing both a dense point cloud and a textured mesh).

In AECO practice they are used for as-built documentation, heritage preservation, construction monitoring, clash verification between design and built, and generating the source geometry for BIM models.

## Why Point Clouds in a Digital Twin?

A BIM model represents design intent; a point cloud represents physical reality. The gap between the two (tolerances, deviations, as-built conditions) is often where problems in construction and facility management live.

Including point clouds in a digital twin provides a ground-truth reference that design models can be compared against, documents the building or site at a moment in time for condition assessment and insurance, gives context for spaces that were never modeled in BIM (common in retrofit projects), and enables precise dimensional analysis without physical access.

## Formats and Conversion

CDT accepts **LAS**, **LAZ** and **E57** on upload. Whichever you send, the file is converted server-side into a **Potree octree**, a spatial tree of tiles at multiple detail levels, and it is that octree the viewer streams. The original file is kept but never rendered directly, so the upload format affects transfer size and conversion time rather than playback. See the [point cloud guide](../guides/point-clouds.md#supported-formats) for what each format stores.

## How CDT Renders Point Clouds

Point clouds render in the **BIM viewer**, through [potree-core](https://github.com/tentone/potree-core), a WebGL renderer for large point clouds driven as an ordinary object in the BIM scene's Three.js graph. It uses an **octree-based level-of-detail (LOD)** system:

1. The dataset is pre-organized into a spatial tree of tiles at multiple detail levels.
2. The viewer requests only the tiles covering the current viewport and camera distance.
3. Close tiles are rendered at full density; distant tiles at progressively coarser density.
4. As the camera moves, new tiles are streamed in and low-priority tiles are evicted.

This keeps memory usage bounded regardless of total dataset size.

Because the cloud is a member of the BIM scene rather than a separate viewer, it shares that scene's camera, clipping planes and measurement tools, which makes comparing design against as-built a single operation instead of two windows.

## Multi-Dataset Scenes

Multiple point clouds can be loaded in one scene simultaneously, which is useful for comparing survey epochs (before and after construction), combining partial scans (indoor plus outdoor, or multiple floors), and overlaying point clouds from different sensors (terrestrial plus aerial). Each dataset has its own visibility toggle, placement and opacity.

## Integration with BIM

A point cloud and one or more IFC models occupy the same BIM scene, enabling comparison of design model against physical reality at element level. A cloud is positioned with the same placement editor the models use, and that placement is stored on the file record.

See the [point cloud guide](../guides/point-clouds.md) for upload, navigation, and display settings.
